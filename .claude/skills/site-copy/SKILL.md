# site-copy — 포트폴리오 카피 규칙

## 절대 규칙 (어기면 다시 쓴다)
1. **인사말·도입 멘트 없음.** "안녕하세요", "환영합니다", "제 소개를 드리자면" 전부 삭제. 첫 문장이 곧 본론이다.
2. **비유 없음.** 대상을 다른 것에 빗대어 설명하지 않는다. 그것이 무엇인지 직접 쓴다.
3. **독자에게 되묻지 않는다.** "~것 같죠?", "궁금하시죠?" 금지.
4. **형용사 금지 목록**: 혁신적인, 열정적인, 다양한, 최첨단, 세상을 바꾸는, passionate, innovative, cutting-edge, game-changing.
5. **근거 없는 숫자 금지.** `_source`가 없는 수치는 문장에 넣지 않는다.
6. **1인칭 자기서사 최소화.** "제가 직접 만들었습니다" 대신 사실을 쓴다. 만든 사람은 사이트 주인이므로 이미 자명하다.

## 문장이 통과하는 기준
각 문장에 대해 묻는다 — **"이 문장을 지우면 독자가 잃는 정보가 있는가?"**
없으면 지운다. 포트폴리오에서 가장 흔한 실패는 내용이 아니라 분량이다.

## 자리별 사양
| 자리 | 분량 | 담아야 할 것 |
|---|---|---|
| 히어로 1행 | 한글 25자 / 영문 12단어 이내 | 하는 일의 정체. 직함이 아니라 활동. |
| 히어로 보조 | 1문장 | 활동의 범위(커뮤니티/회사/앱)를 한 번에 |
| 그룹 설명 | 1문장 | 이 묶음의 공통점 |
| 프로젝트 카드 | 한글 40자 내외 | 무엇인지 + 누구를 위한 것인지 |
| 상세 본문 | 4블록 × 2~4문장 | 문제 / 한 일 / 구조 / 결과 |
| About | 3문단 이내 | 배경, 현재 하는 일, 연락 방법 |

## 상세 본문 4블록
- **문제** — 왜 이걸 만들었나. 개인적 불편도 정당한 이유다. 미화하지 않는다.
- **한 일** — 본인이 실제로 결정하고 만든 것. AI/에이전트를 썼다면 그 사실을 감추지 않는다.
- **구조** — 어떻게 돌아가는가. 에이전트 팀이면 몇 명이 무슨 역할인지.
- **결과** — 지금 상태. 아직 미완이면 "진행 중"이라고 쓴다. 완성된 척하지 않는다.

## 영어 카피
직역하지 않는다. 같은 사실을 영어 독자가 처음 읽는다고 가정하고 새로 쓴다.
한국 고유명사(교회, 커뮤니티, 지역)는 한 번은 짧은 설명을 붙인다.
단, **설명이 대상을 특정하면 안 된다.** 약칭과 도시를 함께 주면 그 둘만으로 기관이 확정된다 —
내부 앱 카드와 합쳐지면 어느 기관의 내부 시스템인지까지 드러난다. 범주만 쓰고 고유명사는 빼라.
존댓말/반말 구분은 영어에 없으므로, 대신 문장 길이를 줄여 톤을 맞춘다.

## 공개 등급별 표현
- `public` — 4블록 전부
- `limited` — 카드 1문장까지만. 상세 본문·링크·화면 설명을 쓰지 않는다. 이유를 묻지 말고 그대로 따른다.
- `private` — 아무것도 쓰지 않는다.

## 사실이 부족할 때
문장을 지어내지 말고 `[[NEEDS: 무엇이 필요한지]]`를 그 자리에 남긴다.
플레이스홀더가 남은 채로 배포되면 QA가 잡는다. 지어낸 문장은 아무도 못 잡는다.

## 수정 요청을 받았을 때
전체를 다시 쓰지 않는다. 지적된 문장만 고친다.
같은 지적이 두 번 나오면 개별 수정 대신 이 문서의 규칙을 고칠 것을 제안한다.
