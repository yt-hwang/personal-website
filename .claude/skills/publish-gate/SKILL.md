# publish-gate — 공개 안전성 검수

## 왜 이 게이트가 필요한가
공개는 되돌릴 수 없다. 삭제해도 검색엔진 캐시, 아카이브, 포크에 남는다.
이 사용자의 프로젝트에는 **회사 트레이딩 전략, 개인 금융·건강 데이터, 교회 성도 정보**가 섞여 있다.
게이트를 통과하지 않은 것은 올리지 않는다.

## 두 번 돈다
1. **카피 작성 전** — 등급을 먼저 정해야 글쓴이가 헛일을 하지 않는다
2. **push/배포 직전** — 마지막 방어선. 여기서 걸리면 배포를 중단시킨다

## 등급
| 등급 | 사이트 표현 |
|---|---|
| `public` | 카드 + 상세 페이지 + 외부 링크 + 스크린샷 |
| `limited` | 카드 1문장 + 태그. 상세·링크·스크린샷 없음 |
| `private` | 미게재 |

판정에는 **반드시 근거 파일 경로**를 단다. 근거 없는 판정은 무효다.

## 도메인별 기본 판정선
- **회사/영업 관련** — 회사가 존재한다는 사실과 본인의 역할은 공개 가능. **전략 로직·파라미터·성과 수치·내부 규정·고객 정보는 전부 비공개.** 기본 `limited`에서 출발한다.
- **개인 금융** — 도구를 만들었다는 사실은 공개 가능. 금액·보유종목·계좌·세율·급여는 전부 비공개. 스크린샷 불가. 기본 `limited`.
- **개인 건강/운동** — 부상 이력, 체중, 심박, GPS 경로, 의료 사진은 비공개. 훈련 시스템의 구조 설명은 공개 가능.
- **교회/커뮤니티 내부 앱** — 성도·멤버의 이름·연락처·사진·출석 정보가 화면에 있으면 스크린샷 불가.
  앱의 목적과 만든 사람은 공개 가능. 내부 전용이면 링크를 걸지 않는다.
- **공개 커뮤니티 활동** — 공개 채널(오픈채팅, 인스타, 밋업)의 링크는 공개 가능.

## 기계적 검사 (배포 직전 필수)

**디렉토리를 손으로 고르지 마라.** 검사 대상은 `git`이 실제로 커밋하려는 파일 전체다.
이 하네스에서 같은 실수를 세 번 했다 — 매번 `app components lib content` 처럼 목록을 적었고,
매번 그 목록 밖에 있던 것이 걸렸다. 마지막은 마이그레이션 스크립트(`ops/*.py`)였는데,
금칙어 목록을 코드에 하드코딩해 둔 탓에 **지우려던 단어를 전부 담은 채** 공개될 뻔했다.

손으로 고른 목록은 반드시 무언가를 빠뜨린다. 목록을 만들지 말고 git에게 물어라.

```bash
git add -A

# 1) 커밋 대상 전체에서 금칙어 — 목록은 _workspace/notes/*.json 의 restrictions 에서 모은다
for w in <금칙어들>; do
  f=$(git diff --cached --name-only | xargs grep -l "$w" 2>/dev/null)
  [ -n "$f" ] && echo "!! $w -> $f"
done

# 2) 커밋 대상에 비밀 파일
git diff --cached --name-only | grep -Ei '\.env$|\.env\.|token|secret|credential|\.pem$|\.key$'

# 3) 커밋 대상에서 키 패턴과 로컬 경로
git diff --cached --name-only | xargs grep -lEn   'sk-[A-Za-z0-9]{20,}|AIza[0-9A-Za-z_-]{30,}|ghp_[A-Za-z0-9]{30,}|xox[baprs]-|C:\Users' 2>/dev/null

# 4) 커밋 히스토리에 이미 들어간 비밀
git log --all --diff-filter=A --name-only | grep -Ei '\.env|token|secret|credential'

# 5) 커밋 대상에 실행 바이너리 / 서드파티 설치물
git diff --cached --name-only | while read f; do
  case "$f" in *.exe|*.dll|*.so|*.dylib|*.wasm|*.jar|*.zip|*.tar|*.gz) echo "!! binary: $f";; esac
  [ -f "$f" ] && [ "$(wc -c < "$f")" -gt 1048576 ] && echo "!! 1MB 초과: $f"
done
```

**서드파티 설치물과 바이너리는 텍스트 grep 의 대상이 아니다.**
위 1~4번은 전부 문자열 검사라, 소스가 없는 실행 파일은 **히트 0 으로 통과한다.**
실제로 외부 UI 린터(impeccable 0.1.5)가 `.claude/skills/` 에 14.0 MiB PE 바이너리를 설치했을 때
1~4번은 전부 무히트였다. 통과한 것이 아니라 **검사 대상이 아니었던 것**이다.

실행 파일이나 1MB 초과 파일이 커밋 대상에 들어오면 판정하지 말고 `NEEDS_USER_DECISION` 으로 올린다.
근거: (1) 내용을 읽을 수 없으므로 무엇이 공개되는지 확인이 불가능하다,
(2) git 은 바이너리를 영구 보존한다 — 파일을 지워도 히스토리에 남고 되돌릴 수 없다,
(3) 재배포는 라이선스 의무를 발생시킨다. `SKILL.md` frontmatter 의 `license:` 선언만으로는 부족하고,
LICENSE·NOTICE 파일이 실제로 동봉돼 있는지 확인해야 한다(Apache-2.0 §4).

`.claude/` 는 `.gitignore` 화이트리스트로 이미 막혀 있으나(에이전트 6 + 스킬 5 만 열림),
`git add -A` 는 저장소 전체를 대상으로 하므로 **그 밖에 떨어지는 설치물은 이 검사가 유일한 방어선이다.**

하나라도 걸리면 **배포 중단**. 히스토리에 이미 들어갔으면 파일 삭제로는 부족하다는 점을 사용자에게 알린다.

히트가 나와도 바로 판정하지 마라 — **원문을 열어 확인한다.** 빌드 캐시(`.next/cache/**/*.sst`)와
소스맵은 오탐이 잦고, 파일명에 `token`이 들어간 디자인 토큰 파일 같은 것도 걸린다.
반대로 "화면에 안 나오니까 괜찮다"도 틀렸다 — **렌더 차단과 커밋 차단은 다른 문제다.**
데이터 파일에 남은 URL은 화면에 없어도 저장소에는 올라간다.

## 이미지 검수
스크린샷은 **전부 실데이터로 간주**한다. 다음을 확인하기 전에는 `cleared: false`를 유지한다:
- 이름, 이메일, 전화번호, 계좌/금액, 주소, 얼굴
- 브라우저 탭·북마크바·URL에 찍힌 내부 도메인
- 알림 배너, 프로필 사진

확인되면 해당 자산의 `content/projects/*.json` → `assets[].cleared`를 `true`로 바꾼다.

## 라이선스
남의 코드·이미지·폰트·아이콘을 쓰면 출처와 라이선스를 사이트 푸터 또는 저장소 `CREDITS.md`에 적는다.
직접 만든 것과 AI로 생성한 것도 구분해 적는다.

## 판단이 서지 않을 때
스스로 결정하지 않는다. `NEEDS_USER_DECISION`으로 올리고, 무엇이 걸리는지와 공개했을 때의 구체적 위험을 한 줄로 쓴다.
"본인 데이터니까 괜찮다"는 자동 승인 사유가 아니다.

## 출력

- 프로젝트별 등급표(등급 / 근거 경로 / 제한 사항)

- 기계 검사 결과 (PASS/FAIL + 걸린 항목)
- 최종 판정: `PASS` 또는 `BLOCKED` (BLOCKED면 배포 금지)
